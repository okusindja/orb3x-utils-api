# Phase 5 — UI Design Contract

> Visual and interaction contract for the new `/docs/mcp` page. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Reuse-first.** This is NOT greenfield. The page is authored as DATA conforming to the existing typed `DocsPage` / `DocsSection` shape and renders through the unchanged `DocsDetailContent` component. ZERO new components, ZERO new CSS, ZERO new tokens. The contract below maps the MCP content onto the existing primitives and flags the ONE place a minimal render/type extension is required (catalog row links).

### Catalog layout decision (Q2)

**One table per domain group (a section per domain group), NOT one 25-row table.** Rationale, matched to existing pages:
- Existing docs pages always pair a short `description` with a focused `table`; a single 25-row table has no place for the curated per-domain section intros that D-01 requires.
- `DataTable` already wraps in `overflow-x-auto` (`site-primitives.tsx` line 431) so each table scrolls horizontally on mobile independently — confirmed responsive, no new work (Q6).
- Suggested groups (discretion per CONTEXT): salary, phone, address+geo (combine — both map to `address-geo`, D discretion), calendar, finance, documents, nif, translation, currency, health. Health can be its own one-row group or folded into a "Platform" group.

### Catalog table columns & rows (Q1, Q3)

Columns: `['Tool', 'Description', 'Docs']`

Each row = `[toolName, oneLiner, docsLinkCell]`:
- `toolName` — plain string, exact registry name (e.g. `salary_net`). The D-01 coverage test asserts these match `registerAllTools`.
- `oneLiner` — localized curated one-liner (D-03). **For `nif_lookup` only**, append the inline latency note to this description string (D-07a) — e.g. `"Look up a NIF on the AGT portal. Live scrape — 5–30 s; set generous timeouts."` (Q3: the inline note lives in the row's description text; do not rely on per-cell emphasis the renderer can't produce.)
- `docsLinkCell` — link to `/docs/[slug]` (D-02). **This is the flagged Extension** — see below.

## FLAGGED EXTENSION — catalog row link (Q1, the one place reuse breaks)

**Problem:** `DataTable` (`site-primitives.tsx` lines 443–453) renders every cell as a bare string: `<td>{cell}</td>`. `DocsTable.rows` is typed `string[][]` (`site-content.ts` line 28). There is NO way to put a working `<Link href="/docs/salary">` inside a table cell with the current type + renderer. D-02 (each row links to the tool's `/docs/[slug]` page) is therefore NOT expressible today.

**Smallest possible extension (recommended — choose ONE; option A preferred):**

**Option A — typed link cell (recommended).** Widen the table cell type to allow an optional structured link cell, and teach `DataTable` to render it.
- `site-content.ts`: add
  ```ts
  export type DocsTableCell = string | { label: string; href: string };
  export type DocsTable = { columns: string[]; rows: DocsTableCell[][] };
  ```
  This stays backward-compatible — every existing `string[][]` rows array still satisfies `DocsTableCell[][]`, so no existing locale file changes.
- `DataTable` in `site-primitives.tsx`: in the cell map, if `typeof cell === 'object'`, render a `next/link` `<Link>` styled `text-primary font-semibold` (matches the accent contract and the existing `relatedSlugs` "Open" link style at `docs-detail-content.tsx` line 175); else render the string as today.
- `DataTable`'s `rows` prop type widens from `readonly (readonly string[])[]` to accept the cell union.
- **Key collision (checker note):** `DataTable` currently uses `key={cell}` (`site-primitives.tsx` line 447), which assumes a string. For an object link cell, switch the key to a stable value (e.g. `typeof cell === 'object' ? cell.href : cell`, or the column index). Fold this into the same ~6-line render change — do NOT keep `key={cell}` for object cells.

Scope: ~2 type lines + ~6 render lines (incl. the key fix). No new component, no new CSS token (reuses `text-primary`). This is in-scope for the planner and is the ONLY render/type change this phase needs.

**Option B — fallback if the team wants zero type changes.** Drop the `Docs` column from the table; instead, after each domain table, render the per-tool links as a `bullets[]` list (the renderer already left-borders bullets) OR rely solely on `relatedSlugs` at the page bottom for navigation. This satisfies "links exist" but weakens D-02's per-row affordance. Use only if Option A is rejected.

**Decision for the planner:** Implement **Option A**. It is minimal, backward-compatible, and fully realizes D-02 within the existing component.
