  <behavior>
    - Under limit: <=60 requests from one IP in the window return NextResponse.next() (pass-through).
    - Over limit: the 61st request from the same IP within 60s returns status 429.
    - 429 body equals `{ error: { code: 'RATE_LIMIT_EXCEEDED', message: <string> } }`.
    - 429 includes a `Retry-After` header (seconds until window reset) and `Cache-Control: no-store`.
    - Isolation: a different IP within the same window is not throttled.
  </behavior>
  <action>
    Create `middleware.ts` at the project root (same level as `next.config.ts`). Constants:
    `WINDOW_MS = 60_000`, `MAX_REQUESTS = 60` (D-01). Module-level
    `const store = new Map<string, { count:number; resetAt:number }>()` — per-instance, no Redis
    (D-04; document the cold-start reset as an accepted free-tier constraint, not a defect).
    `getClientIp(request)` reads `request.headers.get('x-forwarded-for')` and takes
    `.split(',')[0].trim()`, falling back to the literal `'unknown'` (do NOT use `request.ip`).
    `middleware(request)`: resolve IP, reset the window if `now >= entry.resetAt`, increment, and
    when `count > MAX_REQUESTS` return `new NextResponse(JSON.stringify({ error: { code:
    'RATE_LIMIT_EXCEEDED', message: 'Too many requests. Please wait before retrying.' } }), {
    status: 429, headers: { 'Content-Type':'application/json', 'Cache-Control':'no-store',
    'Retry-After': String(Math.ceil((entry.resetAt - now)/1000)) } })`; otherwise
    `NextResponse.next()`. Export `const config = { matcher: ['/api/mcp', '/api/sse'] }` — BOTH
    paths (Pitfall 5: SSE GET on `/api/sse` must not bypass the limiter). Import `NextResponse`
    and `type NextRequest` from `next/server`. This is the primary DoS mitigation (T-01-DoS).
    Note in the SUMMARY that the exact deployed SSE path should be confirmed against MCP Inspector
    in plan 05 and the matcher adjusted if it differs.
