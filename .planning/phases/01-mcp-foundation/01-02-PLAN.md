  <behavior>
    - Success: returns `{ content: [{ type:'text', text: JSON.stringify(result) }] }`.
    - Thrown RouteError: returns `{ isError: true, content: [{ type:'text', text }] }` where text is JSON of `{ code, message, ...details }` (status dropped).
    - Non-RouteError Error: returns `isError:true` with code `INTERNAL_SERVER_ERROR` and the error's message.
    - Non-Error throw: returns `isError:true` with code `INTERNAL_SERVER_ERROR` and a generic message; never re-throws.
  </behavior>
  <action>
    Create `src/lib/mcp/tool-error.ts` exporting a generic HOF `mcpToolHandler<TInput>(fn)`
    that returns `async (input) => Promise<McpResult>`. Mirror the two-branch logic of
    `routeErrorResponse()`: try the wrapped fn, JSON.stringify the result into a single
    `type:'text'` content block; on `instanceof RouteError` emit `{ code, message, ...details }`
    with `isError:true`; on any other throw emit `INTERNAL_SERVER_ERROR`. Import `RouteError`
    via the `@/lib/route-error` alias. Define the `McpResult` type locally as
    `{ content: Array<{ type:'text'; text:string }>; isError?: true }`. No fenced code, no
    module-level mutable state (stateless per D-04). The boundary must NEVER throw — this is
    the information-disclosure mitigation (T-01-04): internal error details collapse to the
    INTERNAL_SERVER_ERROR fallback message, mirroring routeErrorResponse's 500 branch.
  </action>

  </verify>

    - Error text JSON contains `code` and `message` and never the RouteError `status`
    - The handler returns a value for every thrown input — it never propagates an exception
  </acceptance_criteria>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client -> /api/mcp | Untrusted JSON-RPC + tool input crosses into the server |
| tool callback -> client | Error/exception data could leak internals back to the client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Tampering | tool inputSchema (Zod) at app/api/[transport]/route.ts | mitigate | SDK validates every tool input against the Zod `inputSchema` before the callback fires; health takes z.object({}); Phase 2+ tools add `.min/.max/.regex` constraints |
| T-01-04 | Information Disclosure | mcpToolHandler error text (src/lib/mcp/tool-error.ts) | mitigate | Non-RouteError throws collapse to a generic INTERNAL_SERVER_ERROR code+message; internal stack/details never serialized into MCP content |
| T-01-05 | Denial of Service | createMcpHandler dispatch | transfer | Per-IP throttle enforced upstream in middleware.ts (plan 03); stateless handler holds no session memory (MCP-02) |
</threat_model>
